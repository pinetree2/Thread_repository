ARCHITECTURE BLUEPRINT · v2.0

Trend2Threads AI

글로벌 AI/Tech 관심 신호를 사실로 오인하지 않고, 별도 조사·검증·콘텐츠 품질 심사와 Human Approval을 거쳐 Threads에 게시하는 LangGraph Multi-Agent System

HITL
01 · Overview

관심 신호와 사실 근거를 분리한다

Problem

유행하는 정보는 빠르지만 부정확할 수 있고, 생성된 SNS 글을 검토 없이 게시하면 평판·사실성 위험이 발생한다.

Solution

Trend Detection, Research, Verification, Writing, Review, Approval, Publishing을 독립 역할과 조건 Edge로 분리한다.

Outcome

선정 근거·Fact Source·검증 사실·500자 이하 글·품질 점수·승인·게시 ID를 추적 가능한 State로 반환한다.

02 · Input / Output

탐색 범위와 출력 언어는 독립적이다

Input

06 · Agents / Skills

각 역할은 제한된 입력과 Tool만 가진다

Trend Research Skill

API 오류 격리 → 공통 Candidate 변환 → keyword/similarity clustering → 정량 점수.

Fact Verification Skill

공식 자료 우선 → 다중 publisher 비교 → 확인 가능한 문장만 선별 → confidence 계산.

Grounded Threads Skill

verified_facts only → structured output → 숫자 근거 검사 → 500자 제한 → 과장·중복 review.

08 · Threads Publishing

승인 이전에는 외부 쓰기 요청이 없다

1 · Create Container

POST /{user-id}/threads
media_type=TEXT · text=full_text

2 · Publish

POST /{user-id}/threads_publish
creation_id=container_id

3 · Retrieve

GET /{post-id}?fields=id,permalink
ID와 permalink를 State에 저장

필수 Runtime Secret THREADS_ACCESS_TOKEN · THREADS_USER_ID
최소 Scope threads_basic · threads_content_publish
실패 격리 게시 오류는 Trend/Research/Writer를 다시 실행하지 않는다.
09 · Selenium Decision

API가 있는 서비스에는 사용하지 않는다

기본 경로

AI Model Watch, HN, GitHub, YouTube는 API 기반. Selenium은 호출하지 않는다.

허용 조건

공식 API 부재 + JS 렌더링/클릭/스크롤이 필요한 공개 페이지일 때만 선택한다.

구현 규칙

WebDriverWait, headless 선택, 명시적 오류 처리, 동일 TrendCandidate schema.
